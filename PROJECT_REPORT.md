## 2. Концепция проекта

VPN/анти-цензура утилита для Windows с тремя режимами маршрутизации трафика:

- **direct** — напрямую, без туннеля.
- **WARP** — Cloudflare WARP (WireGuard), регистрация аккаунта через `wgcf`.
- **Goida** — сборник публичных конфигов (VLESS / Trojan / Shadowsocks), импортируемых по ссылке-подписке.

**Ключевой сценарий Goida (со слов заказчика):**

> «Goida VPN — это просто сборник ссылок. Например, берём
> `https://github.com/AvenCores/goida-vpn-configs/raw/refs/heads/main/githubmirror/1.txt`
> — там огромная пачка VLESS/Trojan и т.д. Пользователь жмёт "Тест" → все интерфейсы
> отключаются для стабильности → идёт пинг-тест → отсеивается мусор с пингом 200+ →
> внизу появляются страны. Можно ещё сделать доп. спид-тест профилей, но там уже
> ничего убивать не нужно.»

Маршрутизация должна уметь раскидывать домены/приложения по «корзинам» (buckets):
`direct` / `warp` / `goida`, с пользовательскими правилами-оверрайдами.

## 3. Что было в проекте изначально

Ветка `feat/singbox-engine` на момент старта:

### Хорошее (готовое, качественное)

- **Rust-ядро (`core/`)** — уже переехало с Zapret на **sing-box**:
  - `core/src/engine/` — генерация конфига sing-box, TUN, управление службой, статус.
  - `core/src/warp/` — регистрация WARP через `wgcf`.
  - `core/src/goida/` — парсинг подписок (VLESS/Trojan/SS), delay-тест через Clash API, фильтрация.
  - `core/src/rules/` — корзины direct/warp/goida и оверрайды.
  - `core/src/sys.rs` — системные утилиты.
  - **31 unit-тест**, аккуратная структура.
- **Tauri-бэкенд (`app/src-tauri/src/lib.rs`)** — все **17 команд** под новый движок уже написаны и совпадали с ядром.

### Сломанное / недоделанное

- **Фронтенд (`app/index.html`, `app/src/main.js`, `app/src/styles.css`)** — остался
  **старым UI «Фазы 1 — Zapret»**: вкладки WARP/Goida задизейблены, а JS вызывал
  **несуществующие** команды (`get_status`, `list_strategies`, `install_service`,
  `download_zapret_release`, …). То есть приложение собиралось, но GUI не работал
  с новым движком **вообще**.
- **Релизный workflow (`.github/workflows/release.yml`)**:
  - срабатывал только на пуш тега `v*` (который, похоже, ни разу не пушился);
  - `tagName: tandem-vpn-${{ github.ref_name }}` → кривой двойной тег вида
    `tandem-vpn-v0.1.0`;
  - не было ручного запуска.
- **Прочее:** заголовок окна «Zapret», README про Фазу 1, версия 0.1.0,
  последний коммит «Промежуточный комит. Изменено всё».
- **Форматирование:** `cargo fmt --check` падал на `lib.rs` (это тоже валило CI-гейт).

## 5. Почему движок остался sing-box

Заказчик просил «предложи лучше». Я оценил альтернативы **под конкретную концепцию**
(Goida = сборник VLESS/Trojan/SS + WARP + пинг-тест + выбор по странам):

- **sing-box** ✅ — единственный движок, который нативно умеет **и** VLESS/VMess/Trojan/Shadowsocks,
  **и** WireGuard (нужно для WARP), **и** TUN-режим, **и** Clash API для URLTest-пинга «из коробки».
  Ровно этот сценарий.
- **xray-core** ❌ — не умеет WireGuard нормально; для WARP пришлось бы городить
  tun2socks + отдельный костыль.
- **чистый WireGuard** ❌ — не умеет VLESS/Trojan вообще.

**Вывод:** менять ядро смысла нет — оно уже правильное. «Лучше» = довести его до ума,
а не переписать на худшее. Я его отформатировал, прогнал clippy `-D warnings`, тесты.

## 9. Как собрать и выпустить релиз

Локальная сборка Windows-приложения (на машине с Windows):

```bash
# из корня репозитория
cd app
npm ci
npm run tauri build
# артефакты появятся в app/src-tauri/target/release/bundle/
```

Автоматический релиз через CI:

```bash
git tag v0.2.0
git push origin v0.2.0
# либо запустить workflow вручную во вкладке Actions (workflow_dispatch)
```

Workflow соберёт Windows `.msi` / `.exe` и приложит их к GitHub Release с тегом `v0.2.0`.

## 10. Как забрать изменения

Push из песочницы **не прошёл** по одной причине: GitHub App-токен в песочнице
**не имеет права `workflows`**, поэтому отказывается пушить ветку, дерево которой
содержит файлы `.github/workflows/`. Это ограничение платформы, не ошибка кода.

Поэтому изменения отданы двумя способами (файлы лежат в корне рабочей директории):

**Вариант A — git bundle (полная ветка, без конфликтов):**

```bash
git fetch /путь/к/tandem-vpn-singbox.bundle feat/singbox-engine:feat/singbox-engine
git checkout feat/singbox-engine
git push origin feat/singbox-engine
```

**Вариант B — patch (наложить поверх текущей ветки):**

```bash
git checkout feat/singbox-engine
git am tandem-vpn-singbox-complete.patch
git push origin feat/singbox-engine
```

**Вариант C — push силами заказчика:** подключить репо в v0 (Settings → Git) —
там полные права — и я запушу ветку и открою PR.

После пуша — тег `v0.2.0` (см. раздел 9) для релиза.
